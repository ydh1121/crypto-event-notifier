# Viewer table sorting audit — Build 37

전체 Viewer의 표/순위/피드 구조를 검토한 결과다. 정렬은 비교 목적이 분명한 표에만 적용하고, 실시간 피드나 의도적인 랭킹 순서는 유지한다.

## 정렬 적용

- 섹터 > 상세 코인 표
  - 코인명: 기존 검색으로 탐색
  - 24H 거래대금: 오름/내림
  - 24H 등락: 오름/내림
  - 기회점수: 오름/내림
  - 모바일에서는 카드형 행을 유지하고 데스크톱 헤더 정렬만 사용한다.
- PAPER > 코인별 성과
  - 기존 정렬 선택 유지: 수익률 높음/낮음, 거래, 승률, 보유금액, 기회점수.
  - 이 영역은 master list이며 테이블 헤더를 추가하지 않아 모바일 폭을 늘리지 않는다.
- PAPER > 거래소 비교
  - 코인, 빗썸 수익률, 업비트 수익률, 차이를 헤더 클릭으로 오름/내림 정렬한다.
  - 기존 검색/정렬 select와 함께 사용할 수 있다.
- 전략 연구 > 전략 성과
  - 전략명, 수익률, 최대 하락폭, Profit Factor, 거래 수, 승률을 헤더 클릭으로 오름/내림 정렬한다.
- 전략 연구 > 코인별 성과
  - 코인, 수익률, 실현손익, 미실현손익, Drawdown, 완료 거래, 승률을 헤더 클릭으로 오름/내림 정렬한다.
- 전략 연구 > 코인×전략
  - 전략명, 수익률, 실현손익, 미실현손익, Drawdown을 헤더 클릭으로 오름/내림 정렬한다.

## 의도적으로 정렬 UI를 추가하지 않음

- 대시보드 `지금 볼 코인`: 기회점수 기반 추천 랭킹이므로 사용자가 임의 정렬하면 의미가 바뀐다.
- 대시보드 `섹터 자금 집중`: 자금 집중 우선순위 자체가 이 위젯의 의미다.
- 대시보드 `최근 중요 변화`: 최신 이벤트가 맨 위에 추가되는 실시간 피드다.
- 리서치 왼쪽 후보 목록: 현재 기회점수 우선의 탐색 master list이며 상세 판단과 동기화된다. 표가 아니므로 별도 헤더 정렬을 넣지 않는다.
- 자산 보유종목/배분: 평가액 순이 자산 비중 파악의 기본 의미다. 표가 아니라 master/detail 선택 목록이다.
- 기록: 최신 이벤트 prepend가 핵심인 감사 피드다. 과거순 정렬을 허용하면 실시간 새 행 동작과 충돌한다.
- 시스템 구성요소: 운영 흐름 순서대로 고정한 진단 카드이며 성과 비교 표가 아니다.

## 레이아웃 원칙

- 새 정렬은 기존 grid column 수나 min-width를 늘리지 않는다.
- 헤더의 `↕ / ↑ / ↓`만 추가한다.
- 모바일에서 섹터 코인 행은 기존 3-column 카드형 구조를 유지한다.
- 전략/PAPER의 기존 가로 비교 표는 원래의 overflow 영역 안에서만 정렬하며 페이지 전체 폭을 늘리지 않는다.
- 실시간 snapshot 재렌더 후에도 선택한 정렬 상태를 동일 DOM 범위에 재적용한다.
